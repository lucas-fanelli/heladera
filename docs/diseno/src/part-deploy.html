8. Deploy y operación

Plan Spark de Firebase: gratis, sin tarjeta, sin “sleeping”. Si algún día se pasa la cuota diaria, Firestore rechaza operaciones hasta el día siguiente en vez de facturar: es la garantía estructural del $0. Uso estimado de una familia: <1 % de cada cuota.

Lo que hacés vos una sola vez (≈ 30–45 min)

  1. Firebase Console con tu Gmail → “Agregar proyecto” (p. ej. heladera-lista; el ID define la URL heladera-lista.web.app). Sin Analytics.
  2. Firestore → crear base en modo producción, región southamerica-east1 (São Paulo; no se cambia después).
  3. Authentication → habilitar proveedor Anónimo. Revisar en Configuración si existe “limpieza automática de cuentas anónimas” y desactivarla (ver riesgos).
  4. Configuración del proyecto → registrar app Web → copiar firebaseConfig a .env (VITE_FIREBASE_*; las claves son públicas por diseño).
  5. En la PC: npm i -g firebase-tools → firebase login → firebase init (Hosting con dist + Firestore rules).
  6. npm run build && firebase deploy → URL pública HTTPS. Probar en el celular con firebase hosting:channel:deploy prueba (URL temporal) antes de mandarle el link a la familia.
  7. Crear la lista desde la app → anotar 3–4 cosas reales → mandar el link por WhatsApp → armar los accesos rápidos que quieras (QR impreso y/o pegatina NFC con el link corto).
  8. Agregar un segundo Owner al proyecto (otro Gmail de confianza).
firebase.json (lo relevante)
{
  "hosting": {
    "public": "dist",
    "rewrites": [{ "source": "**", "destination": "/index.html" }],
    "redirects": [{ "source": "/h", "destination": "/l/<listId>?anotar", "type": 301 }],
    "headers": [
      { "source": "**", "headers": [
        { "key": "Referrer-Policy", "value": "no-referrer" }
      ]},
      { "source": "/{index.html,sw.js,manifest.webmanifest}",
        "headers": [{ "key": "Cache-Control", "value": "no-cache" }] }
    ]
  },
  "firestore": { "rules": "firestore.rules" }
}
Operación después del día 1
  • Mantenimiento esperado: 0 h/mes.
  • Cambios de UI: npm run build && firebase deploy --only hosting. El service worker se actualiza solo en el próximo arranque (nunca en medio del súper).
  • Cambios de reglas: firebase deploy --only firestore:rules.
  • Backups: Spark no tiene backups automáticos. Botón “Exportar JSON” en el menú (los datos son KB) y, si querés, un cron local ocasional.
  • Rotar el link: crear lista nueva → editar el redirect /h → deploy. El tag no se toca.
  • Desarrollo: contra el proyecto real con una lista de prueba separada. Los emuladores (piden Java) quedan para cuando quieras testear reglas con calma.

Cómo lo verificamos antes de mandarle el link a mamá

  1. Dos navegadores en la PC: agregar en uno, ver aparecer en el otro en <1 s.
  2. DevTools → Network → Offline: agregar y tildar; cerrar la pestaña; reabrir (sigue todo); volver online → llega al otro navegador.
  3. En un Android real, por el canal de prueba HTTPS: instalar la PWA, modo avión, abrir desde el ícono, tildar 3 cosas, salir del modo avión: los tres cambios llegan a la PC. Y el teclado no tapa la barra de agregar.
  4. Probar un acceso rápido (QR o pegatina): abre /h, redirige a /l/<id>?anotar y el input queda listo (el destino lleva el ?anotar explícito porque Hosting no garantiza conservar el query en un redirect fijo; el test de hosting lo fija).
  5. Si hay iPhone: mismo recorrido desde Safari.
